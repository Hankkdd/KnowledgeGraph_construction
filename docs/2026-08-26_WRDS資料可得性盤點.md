# WRDS 資料可得性盤點

日期：2026-08-26
帳號：`hankdd`（NYCU，Students Masters/Undergrad，效期至 2027-07-30）
方法：四輪 information_schema 列舉 + `select 1 ... limit 1` 權限探測 + 日期範圍量測

## 1. 為什麼要做這個盤點

前身 repo 的 Phase 0 因為價格覆蓋不足而停在 Stage 0，且所有 universe 都只能用
current-constituent proxy，帶著無法量化的 survivorship bias。取得 WRDS 之後，
需要先確定哪些 table 真的讀得到，才能決定 universe、圖與連結要怎麼建。

資料庫的 `information_schema` 會列出所有 table，包含沒有訂閱權限的。
因此只列舉表名不足以判斷可用性，必須實際 `select`。

## 4. 三個關鍵發現

### 4.1 舊 SIZ 格式凍結在 2024-12-31

`crsp.dsf` 與 `crsp.stocknames` 的最大日期都是 `2024-12-31`；CIZ 的
`dsf_v2`／`stkdlysecuritydata`／`stksecurityinfohist` 跑到 `2025-12-31`。
CRSP 已於 2025 年初停止更新 SIZ。本 repo 一律使用 CIZ，欄位名稱為
`dlycaldt`／`dlyret`／`dlyprc`／`dlycap` 等。

### 4.2 PIT 成分名單兩路皆封，改由 CRSP 自建 universe

`comp.idxcst_his` 的 S&P 500（`gvkeyx='000003'`）只有 503 列且 `thru` 全為 NULL，
departed = 0，代表只保留現任成分，不是 point-in-time。CRSP 的 index 檔則無權限。

改用市值排序自建：

```
2025-06-30 當日證券數                          10,126
其中有 dlycap                                  10,112
套用 sharetype=NS / securitytype=EQTY /
    securitysubtype=COM / usincflg=Y /
    primaryexch in (N,A,Q)                      3,886
```

每個 rebalance 日取市值前 N，即為完全 point-in-time、survivorship-free 的 universe，
且不需要任何外部成分名單。這比原計畫的 current-constituent proxy 更乾淨。

`stksecurityinfohist` 自帶 `siccd`／`naics`，sector graph 可以完全不碰 Compustat
與連結表；GICS 留待需要更細分類時再引入。

### 4.3 供應鏈可用，但 entity resolution 是自建工作

`compseg.seg_customer`（非 `comp.seg_customer`，後者只有 2020 年後）：

```
全表                                    1976-06-30 – 2026-06-30, 734,842 列
2015 年後 ctype='COMPANY'                117,634 列
  其中具名客戶                            60,391 列 (51.3%)
2015 年後有揭露客戶的供應商                 5,631 家
```

`cnms` 是自由文字。具名的形如 `CVS Health Corp`、`Wal-Mart Stores Inc`、
`Taiwan Semiconductor Manufacturing Co Ltd`；其餘 48.7% 是 `Not Reported`、
`2 Customers`、`4 Customers` 這類匿名彙總，無法對映，只能捨棄。

`ctype` 分布：COMPANY 62,908／GEOREG 51,228／MARKET 31,241／GOVDOM 3,042／
GOVFRN 322／GOVSTATE 279／GOVLOC 34。只有 COMPANY 可用於公司間關係圖。

`wrdsapps.wrds_relationships` 提供 SEC EX-21 子公司清單，含 `clean_company`
正規化名稱與對應 `gvkey`，可作為客戶名稱對映的字典，也能處理母子公司別名問題。

## 5. 對後續設計的結論

1. 價格與 universe 全部走 CRSP CIZ，不依賴任何成分名單。
2. Stage 1 的 sector graph 用 `stksecurityinfohist` 的 `siccd`／`naics`，無連結依賴。
3. 供應鏈圖列為 Stage 2，先做 entity resolution，並在報告中分開列出
   對映成功率與因匿名彙總而損失的比例。
4. limited-attention 檢定改用市值或成交金額分組，取代無訂閱的 IBES 分析師覆蓋數。
5. 關係資料的可得日期用揭露日，不可用 `datadate`。

## 6. 重現方式

探測腳本為一次性診斷，未納入 repo。結論以本文件為準；
若日後訂閱範圍變動，重跑 `select 1 from <table> limit 1` 逐表確認即可。
